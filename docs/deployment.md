# Deployment\n\nAI Agency OS is deployed as a serverless Node.js application on Vercel with Supabase as the data layer.\n\n## Required environment\n\nConfigure these privately in Vercel:\n\n- SUPABASE_URL\n- SUPABASE_PUBLISHABLE_KEY\n- SUPABASE_SERVICE_TOKEN for server-side database operations\n- NVIDIA_API_KEY when using NVIDIA/Nemotron\n- AI_PROVIDER\n- AI_MODEL\n- AI_BASE_URL\n\nNever commit any of these values to GitHub.\n\n## Backend surface\n\nCore endpoints:\n\n- /api/health\n- /api/missions\n- /api/mission-run\n- /api/leads\n- /api/leads/[id]/analyze\n- /api/leads/[id]/proposal\n- /api/proposals\n- /api/approvals\n- /api/dashboard\n\nAutomation-only endpoints remain separately authenticated and are not part of the user-facing API.\n\n## Security model\n\nBrowser requests authenticate with a Supabase Auth access token. User-scoped REST requests now pass that JWT to Supabase so RLS can enforce the signed-in user's policies. Server-only execution paths use the server credential and perform explicit ownership checks before privileged operations.\n\nSupabase publishable keys may be exposed to the browser; server credentials must never be exposed to the client. Supabase documents publishable keys as client-safe when RLS is correctly configured and secret/service credentials as server-only. See: https://supabase.com/docs/guides/getting-started/api-keys\n\nThe frontend stores the access token in sessionStorage, not persistent localStorage, and escapes database/API-controlled values before rendering them as HTML.\n\n## Reliability\n\n- AI calls have a timeout and bounded retry policy.\n- AI responses are schema-validated before mission/lead/proposal state changes.\n- Mission planning is idempotent.\n- Lead analysis reuses the latest analysis unless force is explicitly requested.\n- Active proposal/opportunity and pending task-approval uniqueness is enforced in Postgres.\n- Approval resolution uses an atomic pending-state transition to prevent double approval/rejection.\n- Mission task claiming remains conditional on status=ready.\n- Stale running tasks are recoverable and emit audit events.\n\n## Deployment verification\n\nAfter each push, verify the Vercel production deployment reaches READY, /api/health returns status ok, and authenticated dashboard access works.\n\nRun locally:\n\n    npm install\n    npm test\n    npm run check\n\nThe CI workflow runs syntax checks and tests on pushes and pull requests.\n\n## Activepieces\n\nActivepieces workflow construction and credentials are intentionally kept outside this repository. Existing automation contracts are preserved separately.
